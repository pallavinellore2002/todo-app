# Todo API Reference

This document describes the API currently implemented in `backend/main.py`, backed by MySQL through `backend/database.py`.

- **Local base URL:** `http://127.0.0.1:8000`
- **API prefix:** `/api`
- **Request/response format:** JSON for endpoints with bodies; JSON responses
- **Authentication:** None is implemented.
- **Interactive API docs:** `http://127.0.0.1:8000/docs`
- **Alternative API docs:** `http://127.0.0.1:8000/redoc`
- **OpenAPI schema:** `http://127.0.0.1:8000/openapi.json`

Replace the local base URL with the deployed API URL when using another environment.

## 1. Get All Todos

### Request

```http
GET /api/todos
```

Returns all todos ordered by `id` ascending. If there are no todos, the response is an empty array.

### Success response — `200 OK`

```json
[
  {
    "id": 1,
    "title": "Learn FastAPI",
    "completed": false,
    "created_at": "2026-10-05T09:00:00",
    "updated_at": "2026-10-05T09:00:00"
  }
]
```

### Failure cases

- A database connection or query failure is not handled by a custom API error response and may result in a server error.

## 2. Create a Todo

### Request

```http
POST /api/todos
Content-Type: application/json
```

```json
{
  "title": "Learn FastAPI"
}
```

`title` is required, must be a string, and cannot be empty or whitespace only. The database supplies the ID and timestamps; `completed` defaults to `false`.

### Success response — `200 OK`

The current implementation returns `200 OK` (not `201 Created`) and the created Todo object:

```json
{
  "id": 1,
  "title": "Learn FastAPI",
  "completed": false,
  "created_at": "2026-10-05T09:00:00",
  "updated_at": "2026-10-05T09:00:00"
}
```

### Failure cases

- Missing `title`, a non-string title, an empty title, or a whitespace-only title: `422 Unprocessable Entity`.
- Database connection or query failure: no custom error response is implemented; it may result in a server error.

## 3. Update a Todo

### Request

```http
PUT /api/todos/{todo_id}
Content-Type: application/json
```

`todo_id` is an integer. The request can include `title`, `completed`, or both. Fields omitted from the body retain their existing values.

Change the title only:

```json
{
  "title": "Read the FastAPI guide"
}
```

Change completion status only:

```json
{
  "completed": true
}
```

Change both fields:

```json
{
  "title": "Read the FastAPI guide",
  "completed": true
}
```

In the current implementation, omitted or `null` fields retain their existing values. An empty JSON object is accepted and still updates `updated_at`. A successful update preserves `created_at`, refreshes `updated_at`, and returns the updated Todo object.

### Success response — `200 OK`

```json
{
  "id": 1,
  "title": "Read the FastAPI guide",
  "completed": true,
  "created_at": "2026-10-05T09:00:00",
  "updated_at": "2026-10-05T10:00:00"
}
```

### Failure cases

- No todo exists with that ID: `404 Not Found`.
- An invalid body value or non-integer `todo_id`: `422 Unprocessable Entity`.
- Database connection or query failure: no custom error response is implemented; it may result in a server error.

### Validation mismatch to know about

The requirements say a title must not be empty or whitespace only. The create endpoint enforces this, but the current update request model does **not** enforce it. It also does not explicitly enforce the entity's 255-character limit in the request model. Do not assume update rejects those values until the backend validation is made consistent.

## 4. Delete a Todo

### Request

```http
DELETE /api/todos/{todo_id}
```

`todo_id` is an integer.

### Success response — `200 OK`

The response includes a confirmation message and the deleted Todo object:

```json
{
  "message": "Todo deleted successfully",
  "deleted_todo": {
    "id": 1,
    "title": "Learn FastAPI",
    "completed": false,
    "created_at": "2026-10-05T09:00:00",
    "updated_at": "2026-10-05T09:00:00"
  }
}
```

### Failure cases

- No todo exists with that ID: `404 Not Found`.
- Non-integer `todo_id`: `422 Unprocessable Entity`.
- Database connection or query failure: no custom error response is implemented; it may result in a server error.

## 5. Todo Object

A successful create, list, or update operation returns Todo objects with these fields. Delete returns the deleted object inside `deleted_todo`.

| Field | Type | Description |
|---|---|---|
| `id` | integer | Unique identifier generated by MySQL. |
| `title` | string | Todo text. The entity documentation specifies a maximum of 255 characters at the database level. |
| `completed` | boolean | Completion status; defaults to `false` for newly created todos. |
| `created_at` | string (date-time) | Creation timestamp, serialized as an ISO 8601 date-time. |
| `updated_at` | string (date-time) | Timestamp of the most recent update, serialized as an ISO 8601 date-time. |

## 6. HTTP Status Codes

| Status | Meaning in this API |
|---|---|
| `200 OK` | Request succeeded. Currently used for list, create, update, delete, and `GET /`. |
| `404 Not Found` | Update or delete was requested for a todo ID that does not exist. Response: `{"detail":"Todo not found"}`. |
| `422 Unprocessable Entity` | Request validation failed, such as a missing/invalid create title, invalid body value, or a `todo_id` that is not an integer. FastAPI supplies a `detail` array with validation information. |
| `500 Internal Server Error` | Possible unexpected server/database failure. The backend does not define a custom error contract for these failures. |

FastAPI validation error example:

```json
{
  "detail": [
    {
      "type": "missing",
      "loc": ["body", "title"],
      "msg": "Field required",
      "input": {}
    }
  ]
}
```

## 7. API Endpoint Summary

| Method | Path | Purpose | Success |
|---|---|---|---|
| `GET` | `/` | Return a simple API-running message (does not check the database). | `200` |
| `GET` | `/api/todos` | List todos in ascending ID order. | `200` |
| `POST` | `/api/todos` | Create a todo. | `200` |
| `PUT` | `/api/todos/{todo_id}` | Update a todo's title and/or completion status. | `200` |
| `DELETE` | `/api/todos/{todo_id}` | Delete a todo and return the deleted record. | `200` |

The root endpoint response is:

```json
{
  "message": "Todo API is running"
}
```

The backend's CORS configuration currently allows `http://127.0.0.1:5500`, with credentials, all methods, and all headers. Change the allowed origin if the frontend is served elsewhere.

## 8. Todo Lifecycle

1. **Create:** Send a title to `POST /api/todos`. The new todo is assigned an ID, has `completed: false`, and receives database-generated timestamps.
2. **Read:** Call `GET /api/todos` to retrieve all todos, ordered by ID.
3. **Update or mark complete:** Call `PUT /api/todos/{todo_id}` with the field or fields to change. Omitted fields are retained. `created_at` stays the same and `updated_at` is refreshed.
4. **Delete:** Call `DELETE /api/todos/{todo_id}`. The record is removed and returned in the confirmation response.

## 9. API Validation Rules

### Create (`POST /api/todos`)

- `title` is required and must be a string.
- Empty and whitespace-only titles are rejected with `422`.
- `completed` is not required in the request; the database default is `false`.
- The entity documentation specifies a 255-character maximum, but the current Pydantic create model does not explicitly enforce that maximum.

### Update (`PUT /api/todos/{todo_id}`)

- `title` and `completed` are optional; omitted or `null` values preserve the stored field.
- `completed` should be a boolean.
- The current update model does not reject empty or whitespace-only titles and does not explicitly enforce the 255-character title maximum.
- A todo ID that does not exist returns `404`; a path value that cannot be parsed as an integer returns `422`.

### General

- Invalid request bodies are rejected by FastAPI with `422 Unprocessable Entity` and a validation detail array.
- Database connection/query failures have no custom error response in the current backend.
